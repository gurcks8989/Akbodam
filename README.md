# 악보담 (akbodam)

PDF와 이미지를 보관하고 콘티를 구성하는 오프라인 악보 리더입니다. 교회 사이트, API, 로그인 없이 사용합니다. 작은 서버와 브라우저 화면이 **같은 기기**에서 실행되며 외부 기기의 접속은 받지 않습니다.

## 라즈베리 간편 설치

Raspberry Pi OS **64비트 데스크톱**에서 ZIP을 내려받았다면 압축을 풀고, `package.json`이 있는 폴더에서 터미널을 여세요. 다음 명령 하나로 설치할 수 있습니다.

```sh
bash scripts/setup-pi.sh
```

인터넷 연결이 필요합니다. **명령 앞에 sudo를 붙이지 마세요.** 필요한 시스템 도구를 설치할 때만 관리자 비밀번호를 요청합니다.

설치 도구는 curl·Git·Chromium 등을 준비하고, 호환되는 Node.js와 npm이 없으면 nvm을 통해 Node.js 24를 설치합니다. 이후 앱 의존성과 서버 자동 실행, 로그인 시 전체화면 표시를 등록합니다. 기존에 호환되는 Node.js가 있으면 그대로 사용합니다. 실패하면 오류를 해결한 뒤 같은 명령을 다시 실행할 수 있습니다.

설치 후 OS 설정에서 **데스크톱 자동 로그인**을 켜고 재부팅하세요. 자동 로그인 설정은 스크립트가 변경하지 않습니다. 악보담을 수동 실행 중이라면 설치 전에 종료하세요. 32비트 OS와 데스크톱이 없는 OS는 이 간편 설치의 대상이 아닙니다.

## 수동 실행

Node.js 22.13 이상(권장 24 LTS), npm, Git, 최신 Chromium 계열 브라우저가 필요합니다. Raspberry Pi OS 64비트 데스크톱을 대상으로 설계했습니다. 첫 설치에는 인터넷이 필요합니다.

저장소를 내려받아 실행합니다:

```sh
git clone https://github.com/gurcks8989/Akbodam.git
cd Akbodam
npm ci --omit=dev --ignore-scripts
npm start
```

브라우저에서 `http://127.0.0.1:4173`을 여세요. `PORT` 환경 변수로 포트를 바꿀 수 있습니다. 파이에서는 x86/macOS의 node_modules를 복사하지 말고 파이에서 `npm ci`를 실행하세요.

## 로고와 아이콘

앱 상단과 Linux 실행 아이콘은 `public/logo.png`를 사용합니다. 브라우저 탭에는 16~256px 크기를 포함한 `public/favicon.ico`, 홈 화면용 아이콘에는 `public/apple-touch-icon.png`를 연결했습니다. 기존 Linux 실행 아이콘에 반영하려면 해당 설치 스크립트를 다시 실행하세요.

## 사용 순서

1. 일반 브라우저에서 악보를 검색하고 다운로드합니다.
2. 악보담의 **내 악보 · 파일 추가 → 파일 가져오기**를 누릅니다.
3. 파일 선택 창에서 다운로드 폴더의 파일을 선택합니다.
4. 가져온 악보 옆의 **담기**를 눌러 콘티에 넣습니다.
5. 악보 목록에서 곡을 선택하고 하단 화살표로 페이지를 넘깁니다.

PDF, JPG/JPEG, PNG, 압축하지 않은 XML/MusicXML을 지원합니다. 파일당 최대 50MB, 한 번에 10개입니다. 압축 MXL은 외부에서 XML로 풀어 가져오세요. 암호화 PDF는 암호가 없는 사본이 필요합니다. 파일 확장자와 기본 형식은 검사하지만, 손상된 내부 내용까지 가져오기 단계에서 모두 검증하지는 않습니다. 열기에 실패하면 오류와 재시도를 표시합니다.

콘티에서 ↑↓로 순서를 바꾸고 **빼기**로 콘티 항목만 제거할 수 있습니다. 보관함 파일은 유지됩니다. 같은 곡도 여러 번 담을 수 있습니다. **추가 위치**를 ‘현재 곡 다음’ 또는 ‘콘티 끝’으로 선택하세요. 추가하거나 다른 항목의 순서를 바꿔도 현재 페이지와 확대 비율은 유지합니다. 읽던 곡을 콘티에서 빼면 인접한 곡으로 이동합니다.

화면 하단의 큰 버튼 또는 키보드/발판의 ←·→·PageUp·PageDown으로 페이지를 넘깁니다. 마지막 페이지에서는 멈추며 **다음 곡** 버튼으로 별도 이동합니다. 발판은 해당 키를 보내도록 설정해야 합니다. 확대 시 악보 영역을 터치로 스크롤합니다.

## 즐겨찾기

보관함의 악보 카드에서 별표를 누르면 즐겨찾기에 등록됩니다. **★ 즐겨찾기**를 선택하면 등록한 곡만 표시하며, 제목 검색도 함께 사용할 수 있습니다. 즐겨찾기에서도 악보를 바로 열거나 콘티에 담을 수 있습니다. 별표를 다시 누르면 해제됩니다. 즐겨찾기는 기기에 저장되어 재시작 후에도 유지되고 데이터 백업에도 포함됩니다.

## 저장과 오프라인

- 가져온 파일은 `data/scores/`에 별도로 복사합니다. 다운로드 원본을 삭제해도 남습니다.
- 악보 메타데이터, 콘티, 콘티별 마지막 곡·페이지·확대 배율은 `data/library.json`에 저장합니다.
- 데이터 저장 위치는 `SCORE_DATA_DIR` 환경 변수로 바꿀 수 있습니다.
- 마지막으로 선택한 콘티는 해당 브라우저에 기억합니다.
- PDF.js, Verovio, 폰트 자료는 로컬 node_modules에서 제공합니다. CDN/API를 사용하지 않습니다.
- 설치가 끝나면 인터넷 없이 가져오기·편집·악보 보기가 가능합니다. 단, 프로그램 자체는 실행 중이어야 합니다.
- 백업은 프로그램을 종료한 뒤 **data 폴더 전체**를 복사하세요. 갑작스러운 전원 차단에 대비해 OS의 정상 종료를 사용하세요.

## 파이의 터치 키보드와 전체 화면

Raspberry Pi OS의 화상 키보드(Squeekboard)를 사용합니다. 앱 안에 별도 한글 입력기는 포함하지 않았습니다. 사용하는 OS 버전, USB 터치 장치, 한글 입력 환경에 맞춰 설정하고 Chromium의 검색·이름 입력 칸에서 시험해야 합니다. 자동으로 표시되지 않으면 OS의 키보드 표시 기능을 사용하세요.

초기에는 일반 브라우저에서 시작하고 앱의 **전체 화면** 버튼을 사용하세요. 외부 사이트에서 다운로드해야 할 때는 전체 화면을 해제해 다른 탭으로 이동할 수 있습니다. 앱은 임의의 웹사이트에서 악보를 자동 추출하지 않습니다.

부팅 자동 실행 없이 앱 메뉴의 실행 아이콘만 만들려면:

```sh
bash scripts/install-pi-launcher.sh
```

이 스크립트는 현재 사용자에게 실행 아이콘만 만듭니다. 서버가 꺼져 있으면 아이콘이 서버를 시작한 뒤 Chromium에서 엽니다. 로그인 자동 실행이나 시스템 설정 변경은 하지 않습니다. 아이콘이 서버를 직접 시작한 경우 로그는 프로젝트의 `data/launcher.log`에 남습니다. 자동 실행 서비스가 등록돼 있으면 해당 서비스를 사용하며 로그는 아래의 `journalctl` 명령으로 확인합니다.

## 검증

```sh
npm ci --ignore-scripts
npx playwright install chromium
npm test
npm run test:ui
```

서버 검증은 파일 복사, 재시작 후 보존, 중복 곡, 잘못된 업로드의 전체 취소, 외부 출처 요청 거절을 확인합니다. 화면 검증은 외부 인터넷 요청을 차단한 상태에서 PDF 두 페이지, 중간 삽입, 동일 곡 재사용, 읽기 위치 복원, MusicXML/SVG 및 이미지 표시, 좁은 화면 배치를 확인합니다. 테스트 자료는 임시 저장소에서 사용하며 사용자 보관함에 넣지 않습니다.

## 현재 범위와 제한

교회 API, 휴대폰 리모컨, OCR/PDF→MusicXML 변환, 조옮김, 필기, 보관함 파일 삭제는 아직 포함하지 않습니다. MusicXML 표시는 실험적 기능으로 간단한 샘플만 검증했으며, PDF에서 변환한 실제 악보의 호환성은 아직 확인하지 않았습니다. MusicXML은 Verovio로 고정 A4 페이지를 구성하므로 원본 PDF와 줄바꿈·기호 배치가 다를 수 있습니다. 원본 파일도 함께 보관하고 대조하세요.

실제 Raspberry Pi, USB 터치, 화상 한글 키보드, 발판, 대용량 악보의 성능 검증은 현장 장치에서 별도로 필요합니다. 이 프로토타입의 자동 검증은 macOS Chromium에서 수행합니다.

## 설정에서 폴더로 가져오기

상단 **설정**에서 ‘가져올 악보 폴더’에 전체 경로를 입력하고 **경로 저장**을 누릅니다. 폴더 안의 PDF·사진·MusicXML을 최대 10개 선택한 뒤 **선택한 파일 가져오기**를 누르세요. 하위 폴더 버튼을 누르면 해당 폴더가 저장 경로로 선택됩니다. 하위 폴더를 자동으로 모두 검색하지 않습니다.

경로는 재시작 후에도 유지됩니다. 원본은 변경하지 않으며, 파일 내용이 같은 기존 악보는 중복 복사하지 않습니다. 새 파일을 다운로드한 후에는 **목록 새로고침**으로 확인하세요. 가져온 뒤 **내 악보**에서 콘티에 담으면 됩니다. 복사본 보관 위치도 설정에 표시되며, 이 화면에서 보관 위치 자체를 이동하지는 않습니다.

## 전원을 켜면 자동 실행 (Linux 데스크톱)

Node.js 22.13 이상, npm, Git, curl, Chromium과 systemd 사용자 서비스를 사용할 수 있는 Linux 데스크톱이 필요합니다. Raspberry Pi OS에서는 데스크톱 버전을 사용하세요. 이 도구는 Node.js를 설치하지 않습니다. Node.js부터 준비하려면 위의 `setup-pi.sh` 간편 설치를 사용하세요.

저장소를 내려받은 프로젝트 폴더에서 **최초 한 번**, sudo 없이 데스크톱 사용자로 실행합니다. 이미 터미널에서 `npm start`로 실행 중이면 먼저 종료하세요.

```sh
bash scripts/install-autostart.sh
```

설치 도구는 필요한 앱 의존성을 설치하고 서버를 관리하는 사용자 서비스, 로그인 시 전체화면을 여는 항목, 앱 메뉴 아이콘을 등록합니다. OS 설정에서 **데스크톱 자동 로그인**을 켜세요. 설치 도구가 로그인 설정 자체를 변경하지는 않습니다.

이후 실행 순서는 다음과 같습니다.

1. 기기 전원 켜기 → 악보담 서버 자동 시작
2. 데스크톱 자동 로그인
3. Chromium이 서버 준비를 기다린 뒤 악보담을 전체화면으로 표시

npm이나 서버 실행 명령을 매번 입력할 필요가 없습니다. 서버와 브라우저는 같은 기기에서 실행되며 별도 서버 기기는 필요하지 않습니다. 최초 설치와 업데이트에는 인터넷이 필요하고, 설치된 악보 읽기는 오프라인에서 가능합니다. 자동 실행은 기본 주소 `http://127.0.0.1:4173`을 사용합니다.

전용 전체화면은 Alt+F4로 닫을 수 있습니다. 서버 실행 상태와 오류는 다음 명령으로 확인합니다.

```sh
systemctl --user status akbodam
journalctl --user -u akbodam -n 100 --no-pager
```

자동 실행을 해제하려면 다음을 실행합니다. 서버는 종료되지만 악보와 콘티는 삭제하지 않습니다.

```sh
bash scripts/uninstall-autostart.sh
```

## 네트워크 업데이트

**설정 → 앱 업데이트**에서 현재 버전과 새 버전을 확인합니다. 기본 저장소는 [gurcks8989/Akbodam](https://github.com/gurcks8989/Akbodam)이며, 기존 설정에 다른 주소가 저장돼 있다면 이 주소로 변경할 수 있습니다.

1. 인터넷에 연결한 뒤 **새 버전 확인**을 누릅니다.
2. 설치 가능한 새 버전이 있으면 연주를 마치고 **업데이트 설치**를 누릅니다.
3. 새 버전 다운로드와 의존성 설치, 서버 시작 검증을 기다립니다.
4. 악보·콘티·설정을 자동 백업한 뒤 서버가 새 버전으로 재시작되고 화면이 다시 연결됩니다.

업데이트 확인이나 설치는 사용자가 버튼을 눌렀을 때 진행합니다. 연주 중 자동 설치하지 않으며, 설치 준비 중에는 데이터 편집을 막습니다. 인터넷이 없으면 업데이트를 확인할 수 없지만 기존 악보는 계속 사용할 수 있습니다.

업데이트 설치는 `npm start` 또는 자동 실행 서비스로 시작한 관리 실행기에서 사용할 수 있습니다. 프로그램을 `node server.mjs`로 직접 실행하면 앱 안에서 업데이트를 설치할 수 없습니다.

### 백업과 복구

- **데이터 백업** 버튼으로 설치 전과 별도로 수동 백업할 수 있습니다.
- 새 프로그램은 데이터 폴더의 `releases/`, 백업은 `backups/` 아래에 저장합니다. 기본 데이터 폴더는 최초 설치 폴더의 `data/`입니다.
- 업데이트 후에도 악보와 콘티의 데이터 저장 위치를 유지합니다. 브라우저 데이터도 별도로 유지됩니다.
- 다운로드나 설치 준비에 실패하면 현재 버전을 유지합니다. 새 프로그램이 시작 직후 오류로 종료되면 이전 프로그램으로 복구를 시도합니다.
- **이전 버전 복구**는 프로그램을 되돌립니다. 악보·콘티 데이터를 과거 백업으로 덮어쓰지는 않습니다.
- 백업은 자동 삭제하지 않습니다. 설치할 새 프로그램과 악보 백업을 위한 디스크 여유 공간이 필요합니다.

서버 프로그램 업데이트로 OS, Node.js, 자동 실행 설정 자체를 변경하지 않습니다. 자동 실행 스크립트가 변경됐다면 원래 설치 폴더의 코드를 갱신하고 `bash scripts/install-autostart.sh`를 다시 실행하세요. 데이터 형식 변경이 있는 버전은 별도의 마이그레이션과 백업 복구 절차가 필요합니다.

### 배포 버전 기준

업데이트는 GitHub의 정식 버전 태그를 기준으로 확인합니다. `main`에 코드를 올리는 것만으로는 새 업데이트로 표시되지 않습니다.

저장소 루트에 `package.json`, `package-lock.json`, `server.mjs`가 있어야 합니다. 패키지 이름은 `akbodam`이고, 패키지 버전 `0.2.0`과 Git 태그 `v0.2.0`처럼 버전이 일치해야 합니다. 사전 배포 태그는 제외합니다. 공개 저장소는 바로 확인할 수 있고, 비공개 저장소는 해당 기기의 Git 인증이 필요합니다. 인증 토큰을 저장소 주소나 앱 설정에 입력하지 마세요.

### 확인한 동작과 남은 검증

macOS의 격리된 임시 데이터로 GitHub의 `v0.1.0`에서 `v0.2.0`으로 실제 다운로드·의존성 설치·백업·서버 재시작·콘티 보존을 확인했고, 이전 버전 복구도 확인했습니다. 일반 서버 테스트 4개와 브라우저 기능 테스트 1개가 통과했습니다. 실제 악보 폴더를 사용하는 선택적 테스트는 이번 실행에서 제외했습니다.

Linux 설치 스크립트의 문법 검사는 완료했습니다. **라즈베리에서 전원을 켰을 때 자동 로그인 → 서버 시작 → 전체화면 표시까지의 실제 동작은 아직 기기 검증이 필요합니다.**

### 자동 실행 등록에서 “bad unit file setting” 오류가 발생한 경우

v0.3.2 이전 설치 도구의 `WorkingDirectory` 따옴표 표기를 수정했습니다. Node.js나 npm을 다시 설치할 필요는 없습니다. 기존 악보담 폴더에서 설치 스크립트만 갱신한 뒤 다시 실행하세요.

```sh
curl -fL https://raw.githubusercontent.com/gurcks8989/Akbodam/main/scripts/install-autostart.sh -o scripts/install-autostart.sh
bash scripts/install-autostart.sh
```

수정된 도구는 서비스 등록 전에 systemd 설정 검증을 수행하며, 시작 실패 시 상태와 최근 로그를 표시합니다. 계속 실패하면 출력된 로그를 확인하세요.

### 부팅 서버와 Chromium 실행 보완 (v0.3.4)

자동 실행 설치 시 사용자 linger를 활성화해 데스크톱 로그인 전부터 서버를 시작합니다. 이 단계는 관리자 비밀번호를 요청할 수 있습니다. Chromium은 그래픽 데스크톱 로그인 후 실행되므로 전원만 켜서 화면까지 열려면 OS의 데스크톱 자동 로그인이 필요합니다.

설치 도구는 nvm으로 설치한 Node.js를 자동으로 불러오고, 서비스 등록 후 실제 서버 응답까지 확인합니다. 브라우저 실행기는 터미널에 Node.js가 잡혀 있지 않아도 등록된 서비스를 사용할 수 있습니다. 서버가 준비된 뒤 Chromium을 열며, 실행 로그는 `data/browser-launcher.log`에 저장합니다.

기존 설치를 고칠 때에는 다음 파일을 기존 프로젝트 폴더에서 갱신한 뒤 재등록하세요. 악보 데이터는 건드리지 않습니다.

```sh
(
  set -e
  for script in install-autostart.sh launch-pi.sh install-pi-launcher.sh; do
    curl -fL "https://raw.githubusercontent.com/gurcks8989/Akbodam/v0.3.4/scripts/$script" -o "scripts/$script"
  done
  bash scripts/install-autostart.sh
)
```

자동 실행 제거 도구는 악보담 서비스만 해제합니다. 다른 사용자 서비스가 사용할 수 있으므로 linger 설정 자체는 해제하지 않습니다. 라즈베리 실기기의 재부팅 검증은 별도로 필요합니다.

## 한글 폰트와 키보드 입력

Raspberry Pi OS/Debian 데스크톱의 일반 사용자로 실행합니다. 앞에 sudo를 붙이지 마세요.

```sh
bash scripts/setup-korean.sh
```

Noto CJK·나눔 폰트와 Fcitx 5 한글 입력기, GTK/Qt 연동 모듈을 설치하고 사용자 입력기를 Fcitx 5로 선택합니다. 기존 입력기·폰트 설정은 홈 폴더의 `akbodam-korean-backup-*`에 백업합니다. 기존 Fcitx 입력기 목록은 덮어쓰지 않습니다. 최초 설정에서는 영문 US와 Hangul을 등록합니다.

설치 후 재로그인 또는 재부팅하고, `fcitx5-configtool`에서 **Hangul(한글)**이 있는지 확인하세요. 기존 목록에 없으면 추가 버튼에서 현재 언어만 표시 옵션을 해제하고 Hangul을 찾아 추가합니다. 기본 전환은 **Ctrl+Space**이며 한/영 키는 입력기 설정에서 지정할 수 있습니다. Chromium의 악보 제목 검색창에서 실제 입력을 확인하세요.

이 스크립트는 물리 키보드의 한글 입력과 폰트 표시를 준비합니다. OS 표시 언어, 물리 키보드 배열, 터치 화상 키보드는 변경하지 않습니다. PDF에 이미지로 들어간 글자나 자체 내장 폰트는 OS 폰트 설치로 바뀌지 않습니다. Wayland의 Chromium 입력기 연동은 데스크톱·브라우저 설정에 따라 별도 확인이 필요합니다. 관련 공식 문서: [Fcitx 5 설정](https://fcitx-im.org/wiki/Setup_Fcitx_5), [Wayland 연동](https://fcitx-im.org/wiki/Using_Fcitx_5_on_Wayland/en).

스크립트 문법과 macOS에서의 실행 차단을 확인했습니다. 라즈베리 실기기의 한글 조합 입력은 아직 검증하지 않았습니다. 기존 Chromium 흰 화면 문제를 해결하는 스크립트는 아닙니다.

### Chromium 흰 화면: 비밀번호 저장소 연동

한 라즈베리 실기기에서 서버는 응답하지만 Chromium이 Untitled/Loading에 머무는 현상을 재현했습니다. 전용 프로필에서 `--password-store=basic`으로 실행했을 때 정상 화면 표시를 확인했습니다. 같은 증상이 확인된 기기에 한해 `data/browser-flags.txt`에 이 옵션을 한 줄로 넣을 수 있습니다. 기본으로 강제하지 않습니다. 이 옵션은 OS 키링 기반 암호화를 사용하지 않으므로 해당 전용 프로필에는 웹사이트 비밀번호를 저장하지 마세요. 일반 브라우저 프로필과 분리되며, 되돌리려면 옵션 줄을 제거하고 악보담 브라우저를 다시 실행합니다.

실행기는 Wayland 화면 환경을 감지하면 해당 백엔드를 선택합니다. 데스크톱 로그인 후 실행해야 하며 SSH의 화면 환경은 자동 추측하지 않습니다.
